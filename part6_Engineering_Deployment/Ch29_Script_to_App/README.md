## 本章最重要的六課

### 1. `(1,1) double` 是轉型，不是檢查（§3、練習 1）

| 值 | `(1,1) double` | `(1,1) {mustBeNumeric}` | `(1,1) {mustBeA(t,"double")}` |
|---|---|---|---|
| `"0.5"` | **執行（轉成 0.5）** | 擋下 | 擋下 |
| `true` | **執行（轉成 1，結果全 false）** | 擋下 | 擋下 |
| `int8(1)` | 執行 | 執行 | 擋下 |
| `single(0.5)` | 執行 | 執行 | **擋下（太嚴）** |
| `NaN` | 執行 | 執行 | 執行 |

**`mustBeNumeric` 是參數最好的預設**：擋掉 string 與 logical，接受所有數值型別。
三種都讓 NaN 通過——要擋就另外加。

成本：無驗證 5.09 μs、**`arguments` 5.75 μs**、`inputParser` 103.8 μs（20 倍，訊息也比較差）。

### 2. JSON 不是無損的（§4、練習 2）

| 原本 | 讀回來 |
|---|---|
| 列向量 `[1 2 3]` | **行向量 3×1** |
| string 陣列 | **cell** |
| **`NaN`、`Inf`** | **`null` → `[]`** |
| `single(0.1)` | double（值也變了） |
| `datetime` | **char** |
| 巢狀 struct 裡的 `[5 5]` | 2×1 |

**NaN → [] 最危險**：`Threshold = NaN` 表示自動門檻，存檔讀回來就報「必須是 1×1」。
`ch29_saveConfig`／`ch29_loadConfig` 依**欄位規格**修正型別，**拼錯的欄位報錯並猜使用者想打什麼**：

```
設定檔有不認得的欄位：MinAera（是不是 MinArea？）、Treshold（是不是 Threshold？）
```

### 3. 空的 catch 比沒有 try 更糟（§5、練習 3）

20 個檔、3 個壞的：

| 寫法 | 結果 |
|---|---|
| `try ... catch, end` | **17 個結果，平均 93.0 顆，看起來完全正常** |
| `ch29_runBatch` | 17 成功、3 失敗，**列出是哪 3 個、為什麼** |

而且空 catch 的 `counts(end+1)` 會讓**第 4 個檔之後的結果全部往前錯位一格**——
和第 23 章「只記錄有偵測到的幀」同一件事。

### 4. 回歸測試的基準值是行為，不是真值（§6）

> **我第一版在測試裡寫了 83 顆、平均面積 201.1——是還沒跑就先填的。**
> 實際是 **93 與 189.2**，測試第一次執行就失敗了。

跑出來之後目視檢查疊圖：有 2 個區塊可能是兩顆黏在一起，上緣有幾顆被裁切的沒被算。
**所以 93 是「這個演算法現在的行為」，不是「真實的米粒數」。**

**比較你在意的量，不要比整張遮罩**：

| 改動 | 顆數 | 遮罩差異 |
|---|---|---|
| 輸入改成 single | 93（不變） | **50 像素** |
| 存成 JPEG q90 | 93（不變） | **197 像素** |

回歸測試抓得到真正的改變：

| 重構 | 顆數 | 平均面積 | 測試 |
|---|---|---|---|
| 「更精確」的 `strel("disk",15,0)` | 93 | 189.2 | ✅ 通過（但**慢 5.6 倍**） |
| 改用 `imgaussfilt` 估背景 | **94** | **178.8** | ❌ 抓到 |
| 改用 `medfilt2` 估背景 | **96** | 184.4 | ❌ 抓到 |

**容許誤差要從資料來**（練習 4）：JPEG q50–q95、single、σ≤4 雜訊下平均面積變化
−0.47%～+0.27%，所以 `RelTol=0.01` 有兩倍餘裕；「放大再縮回」+1.67% 會被抓到——那確實是影像改變。

### 5. App 要做薄（§7）

| | 每個測試的耗時 |
|---|---|
| 單元測試（`matlab.unittest`） | 0.1–0.3 秒 |
| **介面測試（`matlab.uitest`）** | **5.7–8 秒（慢 27–61 倍）** |

邏輯放在 callback 裡，就只能用最慢的方式測它。`ch29_GrainApp` 只做
「讀介面 → 呼叫函式 → 顯示結果」，16 個單元測試 1.5 秒跑完，介面只測「按鈕有接到邏輯」。

R2026a 時不用 `.mlapp` 的理由是「它是二進位 zip，`git diff` 看不到改了什麼」——**R2026b 起 App Designer 可以存成純文字（`.m` ＋ `.xml`），這個理由已經不成立**。
不變的理由是：邏輯放在函式裡，App 做薄，才能用快的單元測試測邏輯。

### 6. `profile` 找可疑的地方，重複量測確認值多少（§8、練習 5）

- `profile` 本身讓管線慢 **1.96 倍**，讓小函式迴圈慢 **51.6 倍**
- 它找到了 `strel>MakeDiskStrel`（第 23 章手動計時找到的同一個熱點）
- **練習 5 推翻了我的預期**：我以為 profile 會誇大這個熱點，
  但它的預測（1.37 倍）和第一次實測（1.35 倍）幾乎一樣，
  **反而是兩次實測之間（1.35 vs 1.93）的差距更大**。
  結論是**要重複量**，不是換個工具量一次

## R2026a 注意事項

- **`struct(Name=Value)` 碰到 cell 值會展開成 struct 陣列**：`struct(A=1, L={1,"two"})` 是 1×2
- **`matlab.uitest` 的 `press`／`type` 在 `-batch` 模式可以跑**（`uifigure` 可以不顯示）
- `assumeFail` 讓測試顯示為 Incomplete 而不是 Failed——**用來記錄「已知不適用」的輸入**
- `mustBeNonnegative` 會擋 NaN；`mustBeNumeric`、`mustBeFloat` 不會
