# 第 22 章　工業瑕疵檢測與異常偵測

`[產業]`　建議時數 3 小時　｜　對應舊章：**無**（補課綱缺口 B10）

> ## ⚠️ 關於本章的資料
> **本章預設使用合成的良品／瑕疵影像。** MATLAB 沒有內建的瑕疵資料集
> （`pillQC`、`concreteCrackDataset` 等都要另外下載）。
>
> **合成資料上的分數不能當成對你產線的預期。**
> 本章的重點是**流程與決策方法**，不是「PatchCore 有多強」。
>
> **要換成你自己的資料只要改一個函式**（`ch22_loadDataset`），

## 學習目標

1. 說出異常偵測與監督式分類的取捨，以及什麼時候只能用前者
2. 用 PatchCore 建立一個只需要良品樣本的檢測器
3. **用過殺率與漏檢率決定門檻**，而不是用 F1
4. 用異常圖定位瑕疵，不只判斷有沒有
5. 說出四種異常偵測方法的 API 差異與各自的前提
6. **把整套流程換到你自己的資料上**

## 本章最重要的四課

### 1. 只有良品也能做檢測（第 1、3 節）

| | 監督式分類 | **異常偵測** |
|---|---|---|
| 需要瑕疵樣本 | 要，每類數十張 | **不用** |
| 能偵測沒見過的瑕疵型態 | **不能** | **能** |
| 能說出是哪一種瑕疵 | 能 | 不能 |

PatchCore **不需要梯度訓練**——它把良品特徵存成 coreset，
推論時看新影像離那個集合多遠。**沒有學習率、不會發散。**
24 張 64×64 的合成良品訓練約 **6 秒**。

### 2. 一張髒資料就毀掉一切（練習 2）

24 張良品裡混進 **1 張**瑕疵品：

| 混入瑕疵數 | 瑕疵平均分數 | 分離度 |
|---|---|---|
| **0** | **22.951** | **+716.2** |
| **1** | **3.932** | **−5.0**（分布重疊） |
| 8 | 2.463 | −10.9 |

**一張就跨過懸崖**，而且**沒有任何錯誤或警告**。

原因在機制本身：混進去的那張瑕疵**成了 coreset 的一員**，
於是同類瑕疵離它都很近。

> **良品訓練集的純淨度，比良品的數量重要得多。**
> 練習 3 顯示多收良品的效益有限，但這裡一張髒資料就全毀。

練習 2 也給出偵測方法：**留一法**。
被留下的瑕疵品分數明顯偏高（3.6／2.46 vs 真良品的 1.2／1.24）。
**但它只抓得到零星汙染，抓不到系統性汙染。**

### 3. 門檻由成本決定，不是由 F1 決定（第 5 節、練習 4）

| 錯誤 | 產線上的後果 |
|---|---|
| **過殺**（良品判成瑕疵） | 多一道人工複檢；成本可算、可控 |
| **漏檢**（瑕疵放過去） | 流到客戶端；召回、賠償、商譽 |

期望成本 $= (1-p)\cdot\text{過殺率}\cdot c_{ov} + p\cdot\text{漏檢率}\cdot c_{es}$

**瑕疵率 $p$ 是關鍵。** 產線的 $p$ 通常低於 1%，所以過殺項的權重
$(1-p)\approx 1$、漏檢項只有 $0.01$——
**即使漏檢單次貴 250 倍，過殺的總量仍可能更貴**（良品數量是瑕疵的一百倍）。

> 這和第 20 章的類別不平衡是同一件事，只是換到成本上。

### 4. 三個預期被資料推翻（練習 1、3、加分題）

| 我的預期 | 實測 |
|---|---|
| **瑕疵大小**比對比度致命（下採樣會吃掉小東西） | **對比度才是**：對比度 140→10 掉 79 倍，大小 13→3 只掉 1.9 倍 |
| 良品越多，分離度越高 | **反而下降**（358.6 → 293.1）——因為分離度用 min/max 定義，**對樣本數敏感** |
| 監督式累積足夠瑕疵後會反超 | **兩者都是 1.0000**，合成資料撞到天花板，量不出交叉點 |

第二項是一個指標設計的教訓：**用極值定義的指標會隨樣本數漂移**，
要比較不同樣本數該用分位數或重疊比例。

## 其他實測

- **異常圖的定位**：主教材用「已知瑕疵面積」的偏樂觀做法得到
  IoU **0.604**；練習 5 的誠實版本（自己選門檻）只有 **0.510**。
- **異常圖不適合用邊界指標**：同一個最佳門檻下
  Jaccard 0.510 / Dice 0.675 / **BFscore 只有 0.164**——
  異常圖是下採樣特徵放大回來的，**邊界天生是糊的**。
- **CounTR 少樣本計數**：一個範例 patch，在 `peppers.png` 上數到 **26.4**。
  回傳 `single` 小數（密度圖的積分），`countObjects` **只有一個輸出**。

## R2026a 注意事項

- **`patchCoreAnomalyDetector` 的 `Backbone` 是名稱-值引數。**
  傳位置引數會報「Invalid argument at position 1」——
  **那個訊息看起來像缺套件，其實只是引數形式錯。**
- **`anomalyThreshold(gtLabels, scores, anomalyLabels)`**
  的第三個引數是「**哪些值代表異常**」，不是每個樣本的標籤。
  傳錯會得到「Expected input number 3, anomalyLabels, to be
  integer-valued」——完全指不到真正的問題。
  限制過殺率用 `MaxFalsePositiveRate=0.01`。
- **`evaluateAnomalyDetection` 的 `predLabels` 必須是 logical 向量。**
- **`anomalyMap` 是偵測器的方法**（`exist` 回傳 0）。
- **四種方法的 API 完全不一致：**

| 方法 | 建構 | 訓練 | 要瑕疵樣本？ |
|---|---|---|---|
| **PatchCore** | `patchCoreAnomalyDetector(Backbone=...)` | `train...(normalData, detector)` | **不用** |
| FastFlow | `fastFlowAnomalyDetector(Name=Value)`，`Backbone` 要 **dlnetwork** | `train...(normalData, detector, **options**)` | 不用 |
| **FCDD** | `fcddAnomalyDetector(**network**)` | R2026a：`train...(normalData, **anomalyData**, detector, options)`；**R2026b 可省略 `anomalyData`** | R2026a **要**；R2026b 不用 |
| Student-Teacher | `studentTeacherAnomalyDetector` | `trainStudentTeacherAnomalyDetector` | 不用 |

  **R2026a 的 FCDD 不是單類別方法**——這個差別常被忽略，因為它被歸在同一組 API 裡。
  R2026b 起可以只給良品：實測只用 24 張良品、預設 5 個 epoch，在本機 GPU（T550）上訓練 25.5 秒，良品分數 0.004 ± 0.001（最大 0.005）、瑕疵 0.881 ± 0.153（最小 0.677），完全分開（合成資料）。

## R2026b 注意事項

- **EfficientAD 被移除了**：`efficientADAnomalyDetector` 不在 Visual Inspection Toolbox 裡，
  官方建議改用 `studentTeacherAnomalyDetector`（另需 Student-Teacher 模型支援包）。
- **FCDD 可以不給瑕疵樣本**（見上表）。
- **CounTR 要另裝支援包**：Visual Inspection Toolbox Model for CounTR Object Counting。
  R2026a 包在 AVI Library 裡，所以升級後才會發現少了它。

## 換上你自己的資料

```matlab
data = ch22_loadDataset(Source="folder", ...
    GoodDir = "D:\產線\良品", ...
    BadDir  = "D:\產線\瑕疵", ...
    MaskDir = "D:\產線\瑕疵遮罩", ...   % 選用
    ImageSize = [256 256]);
```

**檢查清單**（練習 6 把它寫成程式碼）：

1. **分數分布圖**：兩個分布重疊嗎？（§4）
2. 良品訓練集有沒有被汙染？（練習 2 的留一法）
3. 良品是否涵蓋所有已知的正常變異？（不同批次、班別、光照）
4. 瑕疵在原圖上佔幾個像素？縮放後還剩幾個？（練習 1）
5. **異常圖指到的是真瑕疵，還是固定的背景／邊框？**
6. 用你的過殺／漏檢成本與真實瑕疵率決定門檻（練習 4）
7. 記錄基準線：分數分布、過殺率、漏檢率、每張秒數

> **第 5 點最容易被跳過，而它最常揭露問題。**
> 異常圖若一直指向影像邊緣或某個固定位置，代表模型學到的是
> **拍攝條件的變異**，不是瑕疵。那時候分數看起來會很好，
> **但換一批影像就崩掉**。一定要看圖。
