# 第 19 章　深度學習物件偵測與模型評估

`[基礎]`　建議時數 5 小時　｜　對應舊章：`11.Object_Detection`（深度學習部分）

## 學習目標

1. 用預訓練偵測器在自己的資料上推論，並用 `evaluateObjectDetection` 評估
2. **說出一個 mAP 數字裡有多少是你自己決定的**
3. 處理**類別體系不對齊**——實務上最常見、最少被寫出來的問題
4. 把偵測誤差拆成定位／重複／背景／漏標，並知道各自要用什麼修
5. 選擇 IoU 門檻與分數門檻，並說出它們各自影響什麼
6. 讀懂偵測訓練與分類訓練的四個差異

> **關於訓練：本章的訓練段落預設不執行。**
> 開發機器是 NVIDIA T550（4.29 GB），跑不動偵測器訓練。
> 程式碼照 R2026a 的 API 寫完整，**實際執行要在記憶體更大的機器上驗證**
> （見文末清單）。本章**所有量化結論都來自預訓練偵測器的推論與評估**，
> 那條路線每張影像只要 0.06–0.07 秒。

## 本章的主軸

偵測的評估流程裡有**四個看起來客觀、其實是你決定**的選擇：

| 決定 | 影響 | 節 |
|---|---|---|
| **類別對應** | **AP 0.261 → 0.483（+85%）** | §3 |
| IoU 門檻 | 0.5–0.75 之間幾乎為 0；放到 0.9 則 AP 崩到 0.031 | §5 |
| 分數門檻 | AP 不受影響，但 precision 20.5% → 72.7% | §6 |
| **配對規則** | **同一批資料，recall 100% vs 84.78%** | §7.1 |

> **報告偵測效能時，這四個選擇必須和 mAP 一起寫出來。
> 只給一個 mAP 是沒有意義的。**

## 最重要的四課

### 1. 類別對應值 85% 的相對 AP（第 3 節）

YOLOX 輸出 COCO 的 80 類；ground truth 只有一個 `vehicle`。
哪些 COCO 類別算 vehicle？**這不是模型能回答的問題。**

| 對應方式 | 框數 | precision | recall | AP |
|---|---|---|---|---|
| 只把 `car` 當車 | 141 | 19.9% | 60.9% | **0.2610** |
| `car` + `truck` | 180 | 20.6% | 80.4% | 0.4678 |
| **`car` + `truck` + `bus`** | 190 | 20.5% | 84.8% | **0.4827** |
| 再加 `motorcycle` | 190 | 20.5% | 84.8% | 0.4827 |

三個觀察：
- **加 `motorcycle` 完全沒效果**——這批影像裡沒有東西被判成機車。
  對應清單要從**實測的類別分布**推導，不要憑空想。
- **recall 漲 24 個百分點，precision 幾乎沒動。** 補進來的是
  原本被漏掉的真車，**不是新的誤判**——漏標的原因是類別名稱不合，
  不是模型看不到。
- 這不是調參數，是**定義任務**。事後挑對應方式 = 用測試集調超參數。

### 2. IoU 分布是雙峰的（第 5 節）

| IoU 門檻 | AP | precision | recall |
|---|---|---|---|
| 0.30 / 0.50 / 0.60 | 0.4827 | 20.5% | 84.8% |
| 0.75 | 0.4740 | 20.0% | 82.6% |
| **0.90** | **0.0307** | **5.8%** | **23.9%** |

平坦，然後懸崖。原因：

| 統計量 | 值 |
|---|---|
| 所有框對最近 GT 的 IoU **中位數** | **0.010** |
| 命中框（IoU ≥ 0.5）的**平均** IoU | **0.871** |

**框要嘛幾乎完美，要嘛根本不在目標上，中間地帶是空的。**
所以門檻在 0.3–0.6 之間移動不改變任何配對。
**這是這個模型 + 這批資料的性質，不是通則。**

### 3. 兩個配對實作，兩個 recall（第 7.1 節）

| 來源 | 配到的 GT | recall |
|---|---|---|
| 課程的貪婪配對 | 46 / 46 | **100%** |
| `evaluateObjectDetection` | 39 / 46 | **84.78%** |

逐張比對找到 4 張不一致的影像。其中一張的 GT 是 `[102 69 27 19]`，
偵測框裡**有兩個的 IoU 是 0.859 與 0.951**，
但官方的 `ImageMetrics.APOverlapAvg` 對該影像回報 **0**。

官方的配對規則沒有完整文件化，所以**本課程不猜它的內部邏輯**。
能確定的是：兩種都合理的實作會給出不同的 recall。

處理方式：**同一份報告的數字全部用同一個工具算**。
本章 §4–§6 一律用 `evaluateObjectDetection`；§7 的貪婪配對
只用來看**誤判的組成**，它的 recall 不當結論。

### 4. precision 20.5% 不代表模型爛（第 7、8 節）

誤差組成：

| 型態 | 數量 | 佔誤判 |
|---|---|---|
| 重複框 | 23 | 16.0% |
| 定位不準 | 1 | 0.7% |
| **背景誤判** | **120** | **83.3%** |

**83% 是背景誤判 → 該提高分數門檻或加硬負樣本，調 NMS 沒有用。**

而且這批是車輛**特寫裁切**，YOLOX 是在 COCO 的**完整場景照片**上訓練的。
它標出 `traffic light`、`stop sign`、`parking meter`——
**那些可能真的在畫面裡，只是我們的 ground truth 只標了車。**

> **20.5% 量的是「模型與標註的一致性」，不是模型的絕對能力。**

## 練習重點

- **練習 1**：類別對應的正確流程（先定規則、後看分數）。
  並回答「看到別的分數更高，為什麼不該改」——**用測試集做任何決定都是洩漏**。
- **練習 2**：把 precision 拉上來。**幾何過濾的比值高出兩個數量級**
  （113.8 / 119.8 vs 分數門檻的 2.22），而且
  **長寬比過濾讓 recall 反而上升 4.5 個百分點**——
  壞框原本會「搶走配對」。三種一起把 F1 從 34.6 拉到 **65.2**。
  > 這打破了「precision 與 recall 必然此消彼長」的直覺；
  > 那個取捨只在調**同一個分數門檻**時才成立。
- **練習 3**：`tiny` vs `small` 的配對比較。
  small 高 0.0929，但 **t = 2.17 < 臨界值 4.30（df=2），分辨不出**。
  分辨不出時該選快的那個。
- **練習 4**：COCO 風格 mAP。mAP@0.5 = 0.5602、**mAP@0.75 也是 0.5602**、
  COCO 平均 0.4430。
- **練習 5**：小目標問題——**結果和通則相反**。
  小 100%、中 100%、**大 85.7%**。因為這是裁切圖，「大目標」是
  填滿畫面、被邊界切掉、缺乏場景脈絡的車。
  （樣本只有 7–8 個，所以正確說法是「沒有證據支持小目標比較難」。）
- **練習 6**：訓練程式碼 + **擴增檢查**（不需訓練就能做，且必須做）。
- **加分題**：敏感度分析（龍捲風圖）。**類別對應影響最大**。

## R2026a 注意事項

- **`evaluateObjectDetection` 不接受只有一個變數的 table**，
  但接受由同一個 table 做成的 `boxLabelDatastore`。
- 度量欄位是 **`metrics.ClassMetrics.APOverlapAvg`**（純量）；
  `metrics.ClassMetrics.AP` 是 **cell**。
  **`metrics.DatasetMetrics` 與 `metrics.ImageMetrics` 可存取，
  但不出現在 `properties(metrics)` 的清單裡**，文件也沒特別提。
  `ImageMetrics` 對除錯（例如 §7.1）非常有用。
- **沒有 `detectionErrorAnalysis`**（`exist` 回傳 0），誤差分解要自己寫。
- 偵測的資料管線是 `combine(imds, blds)`，`read` 回傳**三格**
  `{影像, 框, 標籤}`，不是兩格。
- 每個載入的偵測器都佔顯示記憶體，用完要 `clear`（第 17 章 §10.1）。

## 換機器後要驗證什麼

本章的訓練程式碼（`ch19_trainDetector`、練習 6）**尚未實際執行過**。
在記憶體更大的機器上要驗證：

1. `trainYOLOXObjectDetector` 能否跑完（記憶體、API 相容性）
2. 訓練曲線是否收斂（第 18 章 §10 的四種形狀）
3. **訓練後的 AP vs 預訓練 COCO 模型的 AP**（這是重點）
4. **訓練後是否還會輸出 `traffic light` 之類的東西**——
   自訓模型只有一個類別，所以 §8 的「模型與標註不一致」問題
   應該消失。**這個預測需要驗證。**
5. 每張推論時間是否改變（tiny vs small 骨幹）
6. 練習 6 的擴增檢查在訓練管線上是否仍然通過
