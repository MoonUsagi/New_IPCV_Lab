# 第 09 章　基礎模型分割：SAM 與 SAM 2

`[進階]`　建議時數 3 小時　｜　**全新章節**（R2026a 旗艦功能）

## 學習目標

1. 說明「提示式分割」與前一章所有方法的根本差異
2. 用 SAM 2 做全自動分割與點／框提示分割
3. 理解 embeddings 的架構，並知道它為什麼讓互動式分割變得可行
4. 依情境選擇模型變體，在速度與品質之間取捨
5. **判斷什麼時候該用 SAM、什麼時候傳統方法更好**

## 這一章的定位

第 08 章的所有方法都要你先回答「要用什麼特徵」。
SAM 不問這個，它問的是「**這看起來像一個獨立的物件嗎**」——
這個「物件性」的概念是從上千萬張標註影像學來的。

## R2026a 的重要變更

**預設模型從 SAM 1 改成 `"sam2-large"`。** 舊程式碼的行為會改變，
而且需要安裝 **SAM 2 支援包**（只裝舊的 SAM 支援包會失敗）。

## 實測數據（NVIDIA T550 Laptop GPU，3.5 GB，權重已快取）

### 全自動分割（196×259 影像）

| 變體 | 耗時 | 找到的區域數 |
|---|---|---|
| `sam2-tiny` | **30.0 秒** | 28 |
| `sam2-small` | 34.6 秒 | 28 |
| `sam2-baseplus` | 59.6 秒 | 28 |
| `sam2-large`（**預設**） | **110.8 秒** | 31 |
| `sam-base`（初代 SAM） | 59.8 秒 | 36 |

**預設的 large 比 tiny 慢 3.7 倍，只多找到 3 個區域。**
tiny／small／baseplus 在這張圖上找到完全相同的 28 個區域——
模型大小的差異要在困難影像上才看得出來。

初代 SAM 找到 36 個「更多」，但那是**切得更碎**，不是更好。

### 提示式分割的架構

| 步驟 | 耗時 |
|---|---|
| `extractEmbeddings`（**只需一次**） | 5.54 秒 |
| 每次提示（點或框） | **0.296 秒** |

共用 embeddings：6.72 秒；每次重算：23.33 秒（**慢 3.5 倍**）。
這個 encoder／decoder 的切分，正是互動式分割可行的原因。

## 與傳統方法的正面對決

用第 08 章那組有標準答案的影像（`hands1.jpg`）：

| 方法 | Dice | BFscore |
|---|---|---|
| **SAM 2（一個點）** | **0.9731** | **0.9988** |
| HSV 膚色門檻（Ch.08 最佳） | 0.9441 | 0.7383 |
| ISODATA（灰階） | 0.9050 | 0.7716 |
| Otsu（灰階） | 0.8989 | 0.7700 |

**最值得注意的不是 Dice，是 BF score。**
Dice 只差 3 個百分點，**BF score 差了 26 個百分點**。

BF score 量的是邊界貼合程度——傳統門檻法能大致框對範圍，
但邊界總是鋸齒、有破洞；SAM 給的是乾淨、連續、貼合真實輪廓的邊界。
**這正是 SAM 特別適合做資料標註的原因**（第 17 章）。

## 信心分數高 ≠ 是你要的東西

本章最重要的一個實測：

| 提示點 | 遮罩像素 | 佔全圖 | 信心分數 |
|---|---|---|---|
| 落在圓片上 | 421 | < 1% | 0.9603 |
| **落在背景上** | **38058** | **75%** | **0.9819 ← 更高** |

SAM 沒有做錯——它非常有信心地告訴你「你指的那片背景，
是一個完整連貫的區域」。這個判斷完全正確，只是不是你要的。

> **模型的信心是對「它回答的問題」的信心，不是對「你的意圖」的信心。**

這就是為什麼 `ch09_samAnnotate` 必須用**面積規則**而不是只靠信心分數。

## 核心函式

`segmentAnythingModel` `imsegsam` `extractEmbeddings`
`segmentObjectsFromEmbeddings` `labelmatrix` `labeloverlay`

### 四個 API 陷阱

| 陷阱 | 正確做法 |
|---|---|
| `segmentAnythingModel(ModelName="...")` | 模型名稱是**位置引數**：`segmentAnythingModel("sam2-tiny")` |
| 以為 `imsegsam` 回傳標籤矩陣 | 回傳 **`bwconncomp` struct**，用 `labelmatrix()` 轉換 |
| `ForegroundPoints` 給 [列 行] | 是 **[x y]**；超出範圍會報 `insufficientPrompts`，訊息不會提座標 |
| 以為 `ReturnMultiMask` 的三個遮罩依分數排序 | **不保證排序**，要用 `max(scores)` 挑 |

## 本章函式

| 檔案 | 用途 |
|---|---|
| `code/ch09_samAnnotate.m` | 練習 3 解答：SAM 輔助標註。embeddings 只算一次，並用**面積規則**擋掉誤點背景的結果 |

實測（8 次點擊，其中 1 次故意點在背景）：7 個接受、1 個剔除。
被剔除的那個信心分數 **0.966 是全場最高**。

## 加分題：混合流程的 796 倍

用 SAM 標註少量影像 → 反推傳統方法的參數 → 用傳統方法跑全部：

| 做法 | 處理 10000 張的估計時間 |
|---|---|
| 全部用 SAM | **16759 秒（4.7 小時）** |
| 推導出的傳統法 | **21 秒** |

**加速 796 倍，代價是 Dice 從 1.0 降到約 0.70。**
教材誠實說明了這個品質損失的來源（百分位取得太緊、樣本只有 7 個物件）
以及改善方向。

**划不划算完全取決於下游任務**——計數可能夠用，精密量測就不行。

這正是第 17–22 章的主線：用 SAM／VLM 產生標註，用快的模型上線。
