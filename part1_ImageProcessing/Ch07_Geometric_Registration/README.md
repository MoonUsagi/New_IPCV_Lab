## 本章最重要的一件事

**強度式配準會安靜地失敗。**

用一個旋轉 23°、縮放 0.85 的已知轉換測試：

| 方法 | 回復的旋轉 | 回復的縮放 | PSNR |
|---|---|---|---|
| 未配準 | — | — | 6.89 dB |
| `imregcorr` | **23.05°** | **0.8498** | 14.50 dB |
| `imregtform`（單獨） | **1.81°** ✗ | **0.0106** ✗ | 13.09 dB |
| **兩者串接** | **23.00°** | **0.8460** | **14.62 dB** |
| （真值） | 23° | 0.85 | |

`imregtform` 單獨使用時**完全失敗，但不會報錯**——
它只是回傳一個錯誤的轉換，而整個流程「看起來」跑得很順利。

### 失效門檻在哪（練習 2）

旋轉角度從 0 掃到 40 度：

- **0–16°**：單獨使用可行，誤差 < 0.7°
- **20° 以上**：失敗，且**是跳躍式的**——誤差 29°、47°、甚至 180°
- **串接版**：全程準確，最大誤差 **0.017°**

失敗不是「越來越不準」，而是**突然掉進另一個完全錯誤的解**。
這是局部最佳化的特徵，也是為什麼不能靠「結果看起來合理」判斷成功。

### 三個容易踩到的 API 差異

| 項目 | 說明 |
|---|---|
| `affine2d` vs `affinetform2d` | R2022b 起改用 `*tform2d`。**矩陣慣例不同**（前乘 vs 後乘），混用會得到轉置或反向的結果 |
| `affineOutputView` 的 `"centerOutput"` | **不會放大輸出**。它只是把同尺寸的視窗移到轉換結果的中心。要保留全部內容請用 `"followOutput"` |
| `fitgeotform2d` 沒有 `"translation"` | 支援 similarity / affine / projective 等，純平移要用 `imregcorr(..., "translation")` |

### 這支函式誠實地標示了自己的極限

它擋得住「完全無關的影像」（相似度 0.21 < 門檻 0.40），
但**擋不住多模態配準的錯誤**：

| 情況 | 互相關 |
|---|---|
| 無關影像（胡亂配準） | **0.2114** |
| 真實多模態（正確配準） | **0.1537** |

胡亂配準的分數比正確配準還高——互相關假設亮度有線性對應，
多模態影像不滿足這個前提。

因此函式在 `Modality="multimodal"` 時**不套用絕對門檻**，
改為明白提示「請用 `imshowpair` 人工確認」。
**與其給假的保證，不如說出自己驗證不了。**

## 練習

五題 + 一題加分題。

- **練習 1** 用控制點示範**過度擬合**：模型越複雜，控制點殘差越小
  （1.600 → 1.248），但對未參與擬合的點誤差越大（3.358 → 3.744）。
  這與第 18 章「訓練誤差 vs 泛化誤差」是完全相同的現象。
- **練習 4** 回答「殘差為零代表配準很準嗎」——**不代表**。
  相似轉換 4 個自由度，2 個點剛好恰定，殘差恆為零但參數誤差最大。
  **殘差要有意義，點數必須超過模型的最低需求。**
- **練習 5** 證明非剛性配準可以把**米粒扭成攝影師**。
  256×256 影像的位移場有 13 萬個參數去擬合 6.5 萬個像素——參數比資料還多。
  **非剛性配準的「PSNR 進步」不能當作成功的證據。**
- **加分題**影像拼接的前半段，重疊區 16.9%。第 14 章會用特徵比對做完整版。
